# Спека модуля: habits

## 1. Назначение

Хабит-трекер: пользователь заводит привычки с заданной частотой (каждый день или
определённые дни недели), отмечает выполнение по дням, модуль считает текущий стрик и
публикует события для `tasks` и `motivation`.

## 2. Границы (Scope)

**Входит в модуль:**
- CRUD привычек (создание, список, редактирование, архивация)
- Отметка выполнения на конкретную дату (checkin) и её отмена
- Расчёт текущего стрика и истории выполнения
- Публикация событий о выполнении и о прерывании стрика

**Явно НЕ входит (Out of scope):**
- Напоминания/уведомления (это либо будущий модуль, либо часть `motivation`)
- Групповые/совместные привычки (несколько пользователей на одну привычку)
- Автосоздание задачи по привычке — это подписка модуля `tasks` на событие `habit.completed`,
  реализуется в спеке `tasks.md`, не здесь

## 3. Модель данных

Схема Postgres: `habits`

### `habits.habit`

| Поле | Тип | Обязательное | Ограничения / примечания |
|---|---|---|---|
| id | UUID | да | PK |
| user_id | UUID | да | FK на core.user |
| name | text | да | |
| frequency_type | enum: `daily`, `weekly_days` | да | |
| weekly_days | int[] (0=понедельник..6=воскресенье) | нет | обязательно, если `frequency_type = weekly_days`; NULL при `daily` |
| created_at | timestamptz | да | |
| archived_at | timestamptz | нет | NULL = активна; заполнено = архивирована (мягкое удаление) |

### `habits.checkin`

| Поле | Тип | Обязательное | Ограничения / примечания |
|---|---|---|---|
| id | UUID | да | PK |
| habit_id | UUID | да | FK на habits.habit, ON DELETE CASCADE |
| date | date | да | UNIQUE(habit_id, date) — одна отметка на день |
| note | text | нет | |
| created_at | timestamptz | да | |

Часовой пояс: все даты считаются в фиксированном TZ приложения (`Asia/Tomsk`, задаётся
константой в `core.config`, не per-request) — раз пользователь один. "День" — это
календарная дата в этом TZ, а не UTC.

## 4. API-контракт

| Метод | Путь | Запрос | Ответ | Коды |
|---|---|---|---|---|
| POST | /api/habits | `{name, frequency_type, weekly_days?}` | `Habit` | 201, 422 |
| GET | /api/habits | — (query: `include_archived=false`) | `Habit[]` (с `current_streak`, `done_today`) | 200 |
| GET | /api/habits/{id} | — | `Habit` | 200, 404 |
| PATCH | /api/habits/{id} | частичные поля | `Habit` | 200, 404, 422 |
| POST | /api/habits/{id}/archive | — | `Habit` | 200, 404 |
| POST | /api/habits/{id}/checkins | `{date?: "YYYY-MM-DD"}` (default: сегодня) | `Checkin` | 201, 404, 409 (уже отмечено) |
| DELETE | /api/habits/{id}/checkins/{date} | — | — | 204, 404 |
| GET | /api/habits/{id}/checkins?from=&to= | — | `Checkin[]` | 200, 404 |

Доступ: все эндпоинты фильтруют по `user_id` из JWT — обращение к чужой привычке
возвращает 404 (не 403 — не подтверждаем существование чужого ресурса).

## 5. События

**PUBLISHES:**

| Событие | Когда | Payload |
|---|---|---|
| `habit.completed` | после успешного POST checkin, **только если дата чекина — запланированный день** по расписанию привычки (см. критерий приёмки №6); для чекина в незапланированный день событие не публикуется | `{habit_id, user_id, date, current_streak}` |
| `habit.streak_broken` | при обнаружении пропущенного запланированного дня (см. §6) | `{habit_id, user_id, previous_streak}` |

**SUBSCRIBES_TO:** нет (habits — независимый модуль, первый в цепочке).

## 6. Бизнес-правила и edge cases

- **Расчёт стрика:** считается только по дням, входящим в `frequency_type`/`weekly_days`
  привычки. Отметка на день, не входящий в расписание, сохраняется как checkin, но не
  влияет на стрик (не увеличивает и не может его "спасти").
- **Обнаружение прерывания стрика:** стрик не отслеживается фоновым воркером (нет
  шедулера в MVP) — он вычисляется **лениво** при каждом GET-запросе списка/детали
  привычки: если последний запланированный день до сегодня не имеет checkin, стрик
  считается прерванным. Событие `habit.streak_broken` публикуется в момент этого
  вычисления, не в момент самого пропуска.
- **Дедупликация `habit.streak_broken`:** не более одного раза за календарный день на
  одну привычку — тот же паттерн, что и у `task.overdue` (см. `tasks.md` §6).
  Дедупликация в обработчике (in-process), не персистентным флагом в БД: если стрик
  остаётся прерванным несколько дней подряд, событие публикуется повторно на следующий
  день, а не только один раз до следующего чекина.
- **Повторная отметка того же дня:** `POST /checkins` на дату, где checkin уже есть —
  409 Conflict, checkin не дублируется.
- **Архивация, а не удаление:** архивированная привычка не участвует в расчёте стрика,
  не отображается в списке по умолчанию, но её checkins сохраняются (история не теряется).
  Жёсткое удаление в API не предоставляется в MVP.
- **Изменение `frequency_type` задним числом:** не пересчитывает историю стриков —
  новое расписание действует с текущего момента.

## 7. Критерии приёмки

1. **Given** нет привычек, **When** POST `/api/habits` с `{name: "Бег", frequency_type: "daily"}`,
   **Then** возвращается 201 с созданной привычкой и `current_streak = 0`.
2. **Given** привычка с `frequency_type: "daily"`, **When** POST checkin на сегодня,
   **Then** возвращается 201, публикуется `habit.completed` с `current_streak = 1`.
3. **Given** checkin на сегодня уже есть, **When** повторный POST checkin на ту же дату,
   **Then** возвращается 409, дубликат не создаётся.
4. **Given** привычка с чекинами за 3 дня подряд (включая вчера), **When** GET списка
   привычек сегодня без чекина за сегодня, **Then** `current_streak` в ответе равен 3
   (стрик ещё не прерван — сегодняшний день ещё не закончился).
5. **Given** привычка `daily` с чекином позавчера, но без чекина вчера, **When** GET
   списка привычек, **Then** `current_streak = 0` и публикуется `habit.streak_broken`
   с `previous_streak` равным значению до прерывания.
6. **Given** привычка `weekly_days: [0,2,4]` (пн/ср/пт), **When** пользователь делает
   checkin во вторник (не запланированный день), **Then** checkin создаётся, но
   `current_streak` не меняется и `habit.completed` не публикуется.
7. **Given** активная привычка, **When** POST `/archive`, **Then** привычка пропадает
   из GET-списка по умолчанию, но остаётся доступна через `include_archived=true`, её
   checkins остаются в истории.
8. **Given** привычка принадлежит другому пользователю, **When** GET `/api/habits/{id}`
   от имени текущего пользователя, **Then** возвращается 404.
9. **Given** checkin существует на конкретную дату, **When** DELETE
   `/api/habits/{id}/checkins/{date}`, **Then** возвращается 204, повторный GET истории
   не содержит этой даты.

## 8. Нефункциональные заметки

- Объём данных небольшой (один пользователь, десятки привычек, сотни-тысячи чекинов в
  год) — индексов помимо `UNIQUE(habit_id, date)` не требуется.
- Ленивый расчёт стрика при каждом чтении — приемлем по производительности при таком
  объёме; кэширование не нужно.

## 9. Открытые вопросы

- Нужен ли `target_count` (например, "выпить 8 стаканов воды" — количественная, а не
  бинарная привычка) — в этой версии не предусмотрено, добавить отдельным полем позже,
  если понадобится.
- Нужна ли привязка чекина к времени суток (не только дате) — в этой версии не
  предусмотрено.
